# Judge walkthrough

Start from the repository root with `./run_app.ps1`. The interface reads exported outputs and needs no live exchange connection. The setup guide covers a fresh machine.

## Opening

“PRAHARI reconstructs a credit review desk at historical cutoffs. Each observation carries source and publication provenance. The model development uses public foreign benchmark labels; Indian cases are reserved for evaluation. This release exposes its data gaps openly.”

## Walkthrough

1. Open Time Machine, select the matched panel and a historical cutoff, then search for ITNL, DHFL or Jet. Show observed features and missing-input reasons. Explain that only pre-cutoff public information enters a feature.
2. Open Case Timeline and enable indicator history. Show the exported liabilities/assets or profit/assets history. Change the cutoff and demonstrate that the visible history stops there. Reveal outcomes separately when explaining the documented event.
3. Open Borrower Memo. Show the deterministic credit-language memo and export control. Explain that unscored cases remain unavailable; source-by-source effects require genuine scored endpoints.
4. Open Policy & Metrics. Show benchmark results with their evaluation split, confidence intervals and base rate. Distinguish development from the once-only untouched evaluation wherever present.
5. Show policy parameters and expected costs at the break-even threshold. Explain that the ranked review list is additionally restricted by the configured population-based capacity cap and that an analyst investigates before escalation.
6. Open coverage and the received-peer audit. State clearly that peer integration is deferred and that calibrated Indian probabilities, recall and sealed evaluation have not been claimed.

## Expected questions

**Could this really have caught IL&FS early?** The current Indian reconstruction is not a completed scored evaluation. The report does not claim an early hit. The source-backed history and the leakage safeguards are demonstrable.

**Why are probabilities blank?** Required matching/calibration evidence has not passed acceptance. A blank probability is preferable to an unsupported claim, and the status table lists the missing inputs.

**How is review volume controlled?** The policy uses the configured alert fraction and floor rounding, deterministic ranking/ties and an explicit cap. The same configured costs determine the break-even probability threshold.

**What is still needed?** Accepted historical peers and remaining source coverage/calibration, then committed registration and replay. Independent sealed preparation remains separate from the modeller.

Use the generated report and output tables for all numerical answers; do not quote performance from memory.
